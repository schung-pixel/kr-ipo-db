# kr-ipo-db

한국 IPO(KOSPI·KOSDAQ 신규상장) 데이터베이스의 수집기(1단계)와 조회용 PWA(2단계)입니다. DART 공시에서 지분증권 증권신고서와 그 정정·발행조건확정 건을 모아 공모 건(딜) 단위로 집계하고, 값마다 출처 접수번호를 남깁니다.

## 1단계 범위

| 구분 | 내용 |
| --- | --- |
| 수집 기간 | 2025년 1월 이후 (백필 시작일로 조정) |
| 수집 대상 | 증권신고서(지분증권) 계열 공시 (공시상세유형 C001) |
| 확보 항목 | **희망 공모가 밴드, 확정 공모가, 확정 모집·매출 금액과 주식수, 수요예측 기일·경쟁률·참여 건수, 일반청약 경쟁률·건수, 상장일(공시 원문에서 추출)**, 신고서 기재 기준가, 구주매출 주식수, 대표·공동주관사, 청약·납입일(원문 문자열), 정정 횟수, 발행조건확정 여부, 철회 여부 |
| 갱신 | 평일 18:30(KST) GitHub Actions 자동 실행 |
| 아직 없음 | 상장유형, 기술평가 등급, 비교기업·할인율, 수요예측 결과, 상장 후 수익률 (2~4단계) |

## 구성

```
schema.sql              전체 스키마 (2~4단계 테이블 포함)
collector/dart.py       OpenDART 클라이언트 (공시검색, 기업개황, 증권신고서 주요정보, 공시 원문)
collector/doctext.py    공시 원문에서 희망 밴드·확정가·확정 금액 추출
collector/parse.py      보고서명 분류, 숫자·가격 해석, 기간 분할
collector/store.py      SQLite 저장, 딜 집계, 출처(field_source) 기록, SQL 덤프
collector/pipeline.py   수집 흐름
collector/webexport.py  PWA용 deals.json 생성
collector/run.py        명령행 (restore / backfill / daily / export / export-json / report)
tests/                  모의 응답 기반 테스트
.github/workflows/      평일 자동 수집
data/ipo.sql            DB 텍스트 덤프 (DB 파일은 커밋하지 않음)
docs/                   PWA (딜 목록·필터·상세·월별 통계, 오프라인 지원)
docs/data/deals.json    PWA가 읽는 데이터 (수집 후 자동 갱신)
```

## 시작하기

1. GitHub에 **비공개 저장소**를 만들고 이 폴더 전체를 올립니다.
2. 저장소 Settings → Secrets and variables → Actions에 `DART_API_KEY`를 등록합니다. 키는 opendart.fss.or.kr에서 발급합니다.
3. Actions 탭 → `collect` → Run workflow에서 `mode=backfill`, `from_date=2025-01-01`로 첫 수집을 실행합니다.
4. 이후에는 평일 18:30에 자동 실행되며, 변경이 있을 때만 `data/ipo.sql`이 커밋됩니다.

기업 수가 많아 한 번에 끝나지 않으면 한도 도달 시점에서 멈추고 다음 실행에서 이어갑니다. 처음에는 `max_corps`에 20 정도를 넣어 소량으로 결과를 확인하시기를 권합니다.

## 과거 구간 수집 (10년치)

`data/backfill.json`에 연도 구간 대기열이 있습니다(2024년부터 2016년까지 최근 연도 먼저). 워크플로는 매 실행에서 일일 수집 뒤 대기열을 4시간 30분 동안 처리하고, 구간 하나가 끝날 때마다 `data/ipo.sql`, `docs/data/deals.json`, 대기열을 커밋합니다. DART 일일 한도(020)에 걸리면 그 구간을 미완료로 두고 다음 실행에서 이어 갑니다. 대기열 파일을 고쳐 올리면 바로 한 번 실행됩니다.

원문 확보: OpenDART `document.xml`은 2019년 이전 증권신고서 원문을 주지 않습니다(status 014). 이 경우 DART 공시 뷰어(`dart.fss.or.kr/report/viewer.do`)의 문서 전체 화면을 받아 같은 규칙으로 읽습니다. 2020~2022년 무렵 원문은 XML 선언이 utf-8인데 본문이 EUC-KR인 경우가 있어 인코딩을 판별해 읽습니다.

## 조회 앱(PWA) 배포

`docs/` 폴더가 앱입니다. 수집 때마다 `docs/data/deals.json`이 함께 갱신되어 커밋됩니다.

1. 저장소 Settings → Pages → Source를 `Deploy from a branch`, 브랜치 `main`, 폴더 `/docs`로 지정합니다.
2. 비공개 저장소의 Pages는 GitHub 유료 플랜(Pro·Team 등)에서만 제공됩니다. 또한 Pages 주소는 저장소가 비공개여도 접속 제한이 없는 공개 주소이므로, 공개해도 되는 데이터인지 확인한 뒤 켜십시오. 이 데이터는 DART 공시 가공본이지만 내부 메모나 검수 의견이 들어가는 3단계부터는 접근 제한이 필요합니다.
3. 배포된 주소를 휴대폰 브라우저에서 열고 &lsquo;홈 화면에 추가&rsquo;를 누르면 앱처럼 설치됩니다. 한 번 열면 오프라인에서도 마지막 데이터로 열립니다.
4. `docs/` 파일을 고친 경우 `docs/sw.js`의 `VERSION`을 올려야 기존 기기의 캐시가 갱신됩니다.

로컬에서 확인하려면 `python -m http.server -d docs 8000` 후 `http://localhost:8000`을 엽니다.

## 로컬 실행

```bash
pip install -r requirements.txt
export DART_API_KEY=발급받은키
python -m collector.run restore                       # 덤프가 있으면 DB 복원
python -m collector.run backfill --from 2025-01-01 --max-corps 20
python -m collector.run report                        # 딜 요약
python -m collector.run export-json                   # docs/data/deals.json 생성
python -m collector.run backfill --from 2025-01-01 --refetch-docs   # 원문 추출 실패 건 재조회
python -m unittest discover -s tests                  # 테스트
```

## 상장예비심사 승인 건 (KIND)

증권신고서를 내기 전 단계인 "예심 승인" 회사를 함께 보여 줍니다.

- `python -m collector.run kind`: 한국거래소 KIND 상장예비심사 현황을 조회해 `kind_review` 표에 저장하고, `data/ipo.sql`과 `docs/data/deals.json`을 갱신합니다. 매일 수집 워크플로에서 DART 수집 다음 단계로 돌며, 실패해도 전체 수집은 멈추지 않습니다.
- 선별 기준: 심사결과가 "승인"이고, 결과확정일이 183일(약 6개월) 이내이며, 같은 회사(회사명 정규화 기준)의 DART 증권신고서 딜이 승인 이후에 없는 건만 앱에 "예심 승인"으로 표시합니다. 증권신고서를 낸 회사는 일반 딜로 바뀌고, 상세 화면 '일정·기타'에 예심 청구일·승인일이 붙습니다.
- 수동 보완: KIND 화면에서 내려받은 엑셀(.xls/.xlsx) 또는 CSV를 `data/kind/`에 넣고 `python -m collector.run kind --no-fetch`를 실행하면 같은 방식으로 반영됩니다. 이름이 `_`로 시작하는 파일은 읽지 않습니다.
- 조회 결과가 비어 있으면 응답 원문을 `data/kind/_last_response.html`에 남깁니다(커밋 제외). 첫 Actions 실행 로그에서 "KIND 예비심사 N건 반영" 문구가 나오는지 확인하십시오.
- 주의: KIND 이용약관은 자동화 수단을 이용한 무단 수집(제10조)과 사전 허락 없는 복제·배포(제12조②)를 금지합니다. 저장소와 앱을 외부에 공개하면 이 조항에 걸릴 수 있으므로 비공개로 운영하거나 수동 파일 방식을 쓰는 편이 안전합니다.
- KIND 조회 방식(POST `listinvstg/listinvstgcom.do`, `method=searchListInvstgCorpSub`)은 공개 저장소의 구현을 참고한 것으로, 개발 환경에서는 접속이 차단되어 실제 응답을 확인하지 못했습니다.

## 동작 방식

1. **공시 목록**: 기간을 80일 단위로 나눠 공시검색(C001)을 조회합니다. corp_code 없이 조회하면 기간이 3개월로 제한되기 때문입니다. C001에는 증권신고서뿐 아니라 투자설명서와 증권발행실적보고서도 함께 나오며, 3단계 원문 추출에 쓰도록 `filing`에 보관합니다.
2. **기업 이력**: 주요정보를 아직 받지 않은 기업마다 기업별 공시 이력을 조회해 최초 신고서를 찾습니다. 조회 기간 안에 정정 건만 잡히는 기업이 있고, `estkRs`가 최초접수일 기준이기 때문입니다.
3. **주요정보**: 기업별로 `estkRs`를 조회합니다. 응답은 딜당 마지막 `[기재정정]` 건 한 행이며, 최초 신고서와 발행조건확정 건의 행은 없습니다. 원본 응답은 IPO 후보 기업만 보존합니다.
4. **원문 추출**: IPO 후보 딜마다 `[발행조건확정]` 신고서 원문(document.xml)을 받아 희망 밴드(`공모희망가액 A원~B원`), 확정가(`확정공모가액 N원`), 첫머리의 모집·매출 금액과 주식수를 읽습니다. 발행조건확정 신고서가 여러 건이면 확정가가 읽힌 가장 최근 건을 쓰고, 확정 전 딜은 최신 신고서에서 밴드만 읽습니다. 값마다 근거 문구를 `doc_price`와 `field_source`(method=DOC)에 남깁니다. 딜당 1~2회 호출입니다.
5. **딜 집계**: 태그 없는 신고서가 새 딜을 시작하고, 철회신고서 뒤에 낸 신고서는 [첨부추가] 등 태그가 있어도 재신고로 보고 새 딜을 시작합니다. 증권발행실적보고서가 있으면 `completed`(상장 예정·완료), 철회신고서가 있거나 마지막 신고서가 철회(간주)되면 `withdrawn`입니다. 수요예측 경쟁률은 발행조건확정 신고서의 '수요예측 참여내역' 표 합계, 일반청약 경쟁률은 증권발행실적보고서 '청약 및 배정현황'의 청약수량 ÷ 최초 배정수량, 상장일은 같은 보고서의 '상장일(매매개시일)'입니다. 수요예측 기일은 [발행조건확정] 신고서에 일정표가 없으므로 확정 직전 신고서(정정 포함)의 '수요예측 일시'에서 읽습니다. 같은 신고서에서 상장 시장(코스닥·유가증권 언급 횟수, KIND 예심 시장이 있으면 그 값 우선)과 코스닥 기술특례 여부를 판정합니다. 기술특례는 신고서에 거의 항상 들어가는 상장규정 인용(기술성장기업 의무보유 1년 등)은 무시하고, '기술성장기업에 대한 특례를 적용', '전문평가기관 … A 등급', '상장주선인의 성장성 추천' 같은 회사 자신의 상장 경로 서술만 근거로 삼습니다. 서술이 없고 공모가 할인율 비교군이 기술특례 상장기업이면 '기술특례(추정)'으로 표시합니다. 이익미실현(테슬라) 요건 상장은 기술특례에 넣지 않습니다. `[기재정정]` 등과 `[발행조건확정]` 건은 직전 딜에 붙습니다. 가격·물량은 `estkRs` 행 기준이므로 발행조건확정 이전 값일 수 있고, 이 경우 `estk_before_fixing=1`로 표시합니다.
6. **출처 기록**: 가격·물량·주관사 값마다 접수번호, 응답 그룹, 근거 문구, 추출 방식(API 또는 DOC)을 `field_source`에 남깁니다.

## 통계 화면

상장일 기준(상장 완료 건)으로 집계합니다. 상장일을 원문에서 못 읽은 옛 건은 증권발행실적보고서 제출일로 추정합니다. 기간(전체·최근 5년·최근 3년·연도)과 단위(연·분기·월), 시장(유가증권·코스닥 일반·코스닥 기술특례), 스팩 포함 여부로 거릅니다.

- 기간 확대·축소: 그래프 위에서 두 손가락으로 벌리거나 모으면(컴퓨터는 트랙패드 핀치·Ctrl+스크롤) 기간이 좁아지거나 넓어지고, 확대한 뒤 좌우로 끌면 기간이 이동합니다. 두 번 탭(더블클릭)하면 전체 기간으로 돌아갑니다. 기간 길이에 따라 단위가 연(6년 초과)·분기(2년 초과)·월로 자동 전환되고, 요약 숫자·기술특례·주관사 표도 같은 기간을 따릅니다.
- 연도별(분기·월) 상장 추이: 시장별 누적 막대, 건수↔공모액 전환, 표 보기
- 경쟁률 추이: 수요예측·일반청약 경쟁률 중앙값. 값을 확보한 건이 5건 미만이거나 그 기간 상장 건의 절반 미만이면 표시하지 않습니다(추출 편향 방지).
- 밴드 대비 확정가 위치: 기간별 100% 누적 막대
- 기술특례 분석: 기술특례와 코스닥 일반 비교, 경로, 평가 등급별 건수·경쟁률·상단 이상 비율
- 대표주관사 순위: 건수·공모액·기술특례순, 행을 누르면 해당 주관사 딜 목록으로 이동

## 회사 개요

상세 화면 맨 위에 회사 개요를 보여 줍니다. 우선순위는 ① 요약문(`data/biz_summary.json`, 증권신고서 '사업의 개요' 발췌와 KIND 업종·주요제품만을 근거로 Claude가 작성하고 원문 대조 점검), ② 신고서 '사업의 개요' 발췌(2~3문장), ③ KIND 상장법인 목록의 업종·주요제품입니다. 새로 들어오는 공모 건은 요약문이 생길 때까지 발췌로 표시됩니다. 스팩 합병 뒤 사명이 바뀐 스팩 공모는 신고서 사업 개요로 스팩 여부를 판정해(`is_spac`) 스팩으로 분류합니다.

## 유통물량·보호예수

상세 화면의 '유통물량·보호예수' 칸에 상장일 유통가능 물량(주식수·비율), 보호예수 해제 일정(누적 유통가능, 상장일 기준 날짜), 주주 구분별 보호예수·의무보유 내역, 기관 의무보유확약 비율(수요예측 신청수량 기준)과 확약 기간별 분포를 보여 줍니다.

- 출처는 투자설명서(최근 것부터), 없으면 증권신고서입니다. 딜마다 최대 4건을 보며, 값마다 가장 최근 원문의 값을 씁니다(`deal_lockup` 테이블, `collector/lockup.py`).
- 원문 표를 행 단위로 읽고 서로 맞춰 봅니다. 주주별 매각제한 합계가 '상장예정주식수 − 상장일 유통가능'과 3% 넘게 어긋나면 주주별 내역은 비워 둡니다. 해제 일정 표가 없으면 검증된 주주별 내역으로 누적 일정을 계산하고 그 사실을 화면에 적습니다.
- 상장일 유통가능 물량은 신고서 기준이라 공모주 배정분의 기관 의무보유확약은 반영되어 있지 않습니다.
- 자동 수집은 2020년 이후 딜을 대상으로 합니다(`LOCKUP_MIN_YEAR`). 2016~2019년은 공시 뷰어로 로컬에서 채워 커밋했습니다. 딜마다 최초 신고 후 200일 안의 공시만 원문 후보로 씁니다(이후 유상증자 공시 제외).
- 2026-10-25 기준 채움률: 2020년 이후 749건 중 상장일 유통가능 670건·해제 일정 304건·주주 구분별 내역 253건, 기관 의무보유확약 비율은 스팩 제외 상장 468건 중 365건. 2016~2019년 353건 중 상장일 유통가능 252건·해제 일정 36건·주주 구분별 내역 55건, 확약 비율은 246건 중 118건입니다(2016~2019년은 공시 뷰어로 로컬 추출). 상장주식수와 비율이 2%p 넘게 어긋나는 값과 100%를 넘는 해제 일정은 내보내지 않습니다.

## 알아 두실 한계

- 2016~2019년 원문은 GitHub Actions에서 DART 공시 뷰어에 접속되지 않아 로컬에서 추출해 커밋했습니다(워크플로는 `DART_VIEWER=0`으로 뷰어 대체 조회를 끕니다). 2016~2017년은 발행조건확정 신고서에 수요예측 결과표가 없는 서식이 많아 수요예측 경쟁률이 비는 건이 많고, 기술특례 판정도 서술 방식이 달라 과소 집계될 수 있습니다.
- 대표주관사 순위는 사명 변경·합병사를 현재 사명으로 합산합니다(미래에셋대우→미래에셋증권, 하나금융투자→하나증권, 신한금융투자→신한투자증권, 케이비증권·현대증권→KB증권 등). 목록과 상세에는 공시 당시 사명을 그대로 둡니다.

- **IPO 후보 판별은 추정입니다.** 최초 신고서에 주요사항보고서(rpt_rcpn)가 선행하지 않으면 후보(1), 선행하면 유상증자 등으로 보아 비후보(0)로 둡니다. 실제 IPO 여부는 KIND 상장 현황과 대조해 확정해야 하며, 이는 다음 단계에서 연결합니다. `ipo_basis` 열에 판별 근거를 적어 둡니다.
- **밴드·확정가는 원문 문구에서 규칙으로 읽은 값입니다.** 후보 195건 중 원문에서 가격 문구가 확인된 181건에서 확정 딜 153건의 확정가를 읽었고, 확정가 × 주식수가 모집·매출 금액과 모두 일치했습니다. 스팩 등 단일 희망가는 밴드의 하한과 상한에 같은 값을 넣습니다. 머리말 금액이 확정가 × 주식수와 어긋나면 계산값을 쓰고 근거에 불일치를 적습니다. 해외 기업의 외화 밴드처럼 표기가 다른 건은 읽지 못합니다(`status=no_match`).
- **`filed_price`(신고서 기재 기준가)는 단일가가 아니라 밴드 하단 기준값입니다.** `estkRs` 모집가액은 희망 밴드의 최저가액 기준으로 적혀 있습니다.
- **원문에 공모희망가액·확정공모가액 문구가 없는 후보**(14건, `doc_signal=0`)는 상장사 유상증자 등일 가능성이 높아 앱에 &lsquo;원문 확인 필요&rsquo;로 표시합니다. 자동으로 비후보로 바꾸지는 않습니다.
- 상장일은 증권발행실적보고서에 적힌 예정일입니다(보고서 접수일보다 앞서고 연도만 1년 틀린 오기는 보정). 상장유형, 시장 구분은 KIND 연동 전까지 비어 있습니다(이 수집 환경에서는 KIND 접속이 차단되어 있습니다).
- 일반청약 경쟁률은 청약금액이 확정가 또는 증거금(50%)과 맞는지 확인한 뒤 씁니다. 건수·수량 칸이 바뀌어 기재된 공시는 금액으로 확인되는 칸을 쓰고, 어느 쪽도 맞지 않으면 비워 둡니다(2025.1~2026.10 비스팩 상장 109건 중 3건). 밴드 변경 이력(최초 밴드 대비 조정)은 아직 수집하지 않습니다.
- 2025년 3월 구간 시험 수집에서 후보로 잡힌 7건은 모두 실제 IPO(스팩 1건 포함)였고, 유상증자 3건은 비후보로 분류됐습니다. 전체 기간의 정확도는 KIND 대조로 확인해야 합니다.
